# 学习资料制作规范

版本：2.0。当前模式：快速理解大模型全貌，暂不做实验。参考依据见 [sources.md](sources.md)。

## 学习者与当前目标

用户有 3 年 C++/JavaScript 开发经验，每天可安排 4 小时。第一轮追求理解主要机制、概念区别和整体关系；不安排环境安装、编码任务、部署或压测。工程实践在用户进入深入阶段后另行安排，不能将第一轮知识学习等同于工程能力。

## 正文怎么写

每章围绕一个明确问题，以具体例子连续展开，先讲必要性与机制，再引入术语。用同一个例子逐步增加一个条件，避免一次加入多个抽象层次；讲清本章与整体地图的连接，结尾自然接上下章的问题。

相关句子写成连贯段落，减少零碎换行；公式优先使用 Markdown 原生可读的 Unicode 符号与上下标，不依赖 `$...$`、`$$...$$` 等 LaTeX 渲染；符号、单位、形状有解释。核心术语与关键结论适量加粗。复杂关系用图并配简短说明，图源保存在课程目录或正文中。省略通用编程教学、模板话术、重复的目标宣告和非必要实现细节。

具体算例可用于解释，但不要求编写或运行代码。数学以支撑理解为限，不因篇幅短而省略必要的因果步骤。来源用于支持事实，不能代替正文。课时和掌握标准如有必要放附页，不打断阅读。

## 章末固定内容

每个编号课时视为一章，包含“正文 → 助记卡片 → 自测题”。正文内部的小节不重复布置整套卡片与题目。

- 助记卡片通常 6～10 张，每张一问一答，答案一两句。统一使用原生 Markdown 的加粗问题和引用块答案，不使用 HTML 折叠标签。一次只测试一个概念或关系，避免长段摘抄。
- 卡片题目保留成立前提：明确对象、运算及符号含义。不得把矩阵的形状写成参与运算的数据；“矩阵乘法”“向量点积”“逐元素乘法”不可省略为含糊的“相乘”。准确性优先于压缩句数。
- 自测题通常 5～8 道，预计 10～20 分钟，覆盖概念解释、易混辨析、场景判断和少量心算。只考正文已讲的必要知识。
- 参考答案另页，给结论及简短理由；不把题目变成代码、实验或大篇幅矩阵运算。
- 卡片用于回忆，题目用于判断能否应用；两者避免逐字重复。知识点存在误解时，补一段有针对性的解释，不重讲全章。

## 节奏与进度

每章先按 60～100 分钟估算，可根据难度调整，每天通常 2 章，余下时间用于复习与答疑。D01 已投入的阅读时间不重置，也不需要为满足时间预算重学已懂内容。不再固定一章占满 4 小时。

先自己回忆再展开卡片；次日短暂复习前一日卡片，数日后重做错题。复习时间按实际遗忘调整，不自动创建提醒。能解释核心机制与区别即可进入下一章，小细节记作待回访；不得未经作答就宣称掌握。

## 事实核对与交付

稳定概念参考教材、原始论文或权威文档；模型特性与接口等易变内容生成时核对官方资料，并标明适用版本或日期。区分教学简化、经验判断、手算示例与实际验证，不能编造数据或学习记录。

制作顺序：读取用户反馈与进度 → 确定本章问题及必要范围 → 写连续讲解与必要图示 → 编写卡片、自测与答案 → 检查因果承接、数值、引用和本地链接 → 更新入口与资料状态。

保留旧代码、实验、长练习及用户笔记。旧实验标注为后续深入资料，从第一轮主入口撤下，不删除或继续扩展。用户进入实操阶段时，再恢复环境说明、代码复现与实际验证要求。

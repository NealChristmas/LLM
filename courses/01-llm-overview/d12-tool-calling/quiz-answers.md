# D12 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是区分模型提出调用与程序真实执行。

1. 模型直接输出的是 Token 序列，文字不会自动改变审批系统。只有外部程序在校验参数、权限和业务规则后执行写操作，才能确认申请是否创建；最终还要依据工具返回结果回答。
2. 至少要说明工具名称、用途、必填参数、参数含义和类型。结构化调用让程序能按固定字段解析和校验，避免从自由文本中猜测调用意图。
3. “随便哪天”不满足明确日期要求，可能无法被接口接受，也可能触发错误业务行为。程序应检查必填字段、类型与格式、业务规则和权限，必要时让模型向用户补问。
4. 查询天气通常只读且易于重试；付款会改变外部状态并造成资金影响，需要更严格的权限、金额校验、用户确认、审计和防重复机制。用户确认必须由可信程序记录，不能只相信模型的文字。
5. 为同一个逻辑请求携带稳定的请求标识，由执行系统识别重复请求并返回原结果，而不是再次创建。这是在副作用操作中应用幂等性。
6. 工具已经返回失败，模型却将其解释为成功，主要属于结果理解或最终生成错误；也应确认程序是否把状态清楚地反馈给模型。
7. “告诉我规则”可由 RAG 检索制度并生成有依据的回答；“提交报销单”需要工具调用，由程序校验并写入报销系统。实际场景也可能先用 RAG确认规则，再用工具执行。

第 1、2 题不清楚时回看第 1、2 节；第 3～5 题回看第 3、4 节；第 6 题回看第 5、6 节；第 7 题回看第 7 节。

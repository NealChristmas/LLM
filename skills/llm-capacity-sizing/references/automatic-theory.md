# 自动理论测算

用户不提供理论结果 JSON。智能体收集业务需求、实测基线、模型 config.json 和部署条件，提取参数并调用计算工具；内部产生的 JSON 用于追溯，不转成新的用户填写任务。

先按[模型适配流程](model-adaptation.md)形成有来源、单位与适用条件的计算方案，再选择工具。固定流程，不固定底层公式；config结合模型实现、量化、缓存与并行/卸载布局决定算法。当前导入器和通用旧计算器仅覆盖部分特例，不代表所有模型必须沿用其字段与公式。

未提供配套模型资料时，先从Hugging Face官方模型仓库下载同一提交的配置、README、推理实现、权重索引及必要报告，记录提交哈希与文件摘要。只读取代码，不执行；索引的total_size是存储字节，不是参数个数，API统计还可能包含量化打包与元数据。官方原生FP4/FP8缓存结论不能直接替代部署W8A8C16的缓存预算；输入与生成激活参数不同的架构须分阶段采用依据，不能共用一个参数值。

## 从配置到预算

| 输入依据 | 可用于计算 | 仍需注意 |
|---|---|---|
| 同版本实现及张量清单、实际精度与布局 | 分组计算权重数据、量化元数据、复制与卸载；简单统一精度才采用参数数×字节数 | 卡上与主机内存分别统计，不能仅看全模型总参数 |
| 输入/生成实际计算图或分别声明的激活参数 | 分阶段计算工作量；2×激活参数仅为矩阵线性层近似 | 注意力、压缩、草稿与验证等额外工作另计，不能共用单一阶段值 |
| 缓存对象、形状、窗口/压缩/共享及分配规则 | 按实际对象求和；标准KV公式仅适用于已核对的标准全注意力结构 | 区分全局/滑窗/索引/固定状态和复制；不统一按每Token线性增长 |
| 硬件及部署资料 | 可用显存、有效输入/生成算力与完整部署组 | config没有这些数据，不默认填效率或卡数 |
| 用户并发、长度、TTFT、TPOT、增长及备用 | 本次负载预算与资源组数 | 理论预算不能预测或证明P95达标 |

`assess` 自动解析已关联配置，计算可确定的参数声明、权重张量、线性层计算量、标准缓存和上下文检查。数值进入客户 Markdown 正文及依据附录。没有显式参数量时，智能体先核对同版本实现或张量清单；当前解析器不会自行推导未知架构的参数量。多模态子配置不代表全模型；混合量化不能用统一字节数覆盖。

这些为辅助解析，不自动等于完整模型预算。先识别张量、算子和布局，再复用适用方法；有充分依据但现有工具未覆盖时，在本轮目录编写确定性本地计算脚本并验证，必要时扩展工具库。不会要求用户提供理论JSON，也不将“工具未适配”伪装成缺少用户数据。

昇腾硬件型号与官方规格见[硬件基线](hardware-baselines.md)。规格峰值只可作为理论输入的硬件上限；要计算理论卡数还须明确设备实际可用内存、对应精度与算子的有效效率，以及具体部署组布局和通信开销。

DeepSeek-V4.1-Flash须适配输入/生成不同路径、压缩和共享缓存、Engram与PD布局，不能套普通KV公式或借用旧版V4的284B/13B。公开结构资料先自行核实并据此适配；实际必要部署/性能依据仍不足时，才向用户询问并等待。用户明确无法补充且不调整范围后中止，不生成不完整客户结论。

## 数值计算工具

仅当共享输入/生成资源、同质卡、完整权重副本、单一激活参数与等效缓存假设均成立，且数值及来源已核对时，智能体才调用原通用计算器：

```bash
python scripts/sizing.py theory-calculate --help
```

按帮助逐项传入数值参数，无需 `--inputs` 文件。`--total/--active` 为十亿参数，`--bytes` 为目标权重每参数字节数，`--cache` 为参考精度下 KiB/Token，`--cachePrecision/--kv` 分别为参考和目标缓存格式；`--cacheLength` 为兼容原预算记录保留的参考长度，不参与按Token缓存公式。`--memory/--runtime` 为每卡 GiB；`--peak` 为与效率定义一致的每卡 TFLOPS；`--usable/--prefillEfficiency/--decodeEfficiency/--timeBudget/--growth/--weightExtra` 为百分数。`--group` 为完整副本卡数，`--slots` 为服务器卡槽数，`--parallel` 为模型同时调用倍数；用户已提供模型并发时填1。其余业务输入单位与需求模板一致。

通过重复 `--basis` 记录模型配置摘要、参数提取依据、硬件型号与精度、缓存公式、部署布局及每项预算假设。该参数只记录来源，不意味着内容已核验。`--config-form` 必须明确为 `shared`、`PD混合` 或 `混合部署`；PD分离及未知布局拒绝计算。其他 `--config-*` 绑定芯片、框架、CPU与并行策略。

`--out`输出该命令的原输入、单位、公式版本、来源和结果。内部可用`prepare --theory`接入已支持格式；不能要求用户提供文件。旧计算器以最大长度突发预算为假设，不自动适用于闭环或均值负载；不能统一用“并发×长度×每Token计算量÷TTFT”预测平均TTFT。

**不能凑齐字段就套公式，也不能因工具未适配就中止。** PD分离、特殊缓存和不同阶段路径，在依据充分时由智能体扩展计算并验证；真实必要依据仍缺少时才询问用户。不能猜效率、改变部署类型或用基线卡数反填理论假设。

新适配结果保留适配身份、算法/脚本摘要、输入来源、逐阶段/逐设备结果、公式、假设与未覆盖项。现有`prepare --theory`仅识别旧理论格式；超出格式时扩展导入、重算和报告路径并验证，不能伪装成旧版calculationVersion=1.1.0。报告数字、公式与适配结果一致后才交付；尚未实现的适配如实标记，不能写成自动支持所有模型。

# 中文技术学习资料审查清单

按顺序执行。若项目有更具体的规范，以项目规范为准，并在报告中说明采用了哪些本地约束。

## 1. 范围与读者

- 本章是否围绕一个可回答的问题，而不是围绕术语清单？
- 难度是否建立在已确认的背景上？是否把“会编程”误当成“懂数学或机器学习”？
- 内容是否符合当前学习阶段？速成阶段不应被实现细节、实验和环境配置打断。
- 本章在知识地图中的输入和输出是否清楚？是否自然接续上一章并留下下一章真正需要解决的问题？

## 2. 正确性与证据

- 公式、维度、符号、数值例子和推导是否正确？逐步独立复算关键计算。
- 变量是否在首次使用附近解释对象、下标、单位或取值范围？只有符号多且反复使用时才需要符号表。
- 同一对象是否始终使用同一术语和符号？改变符号时是否说明映射？
- 图、正文、卡片、题目与答案是否给出一致关系？
- 稳定知识是否有可靠依据；易变信息是否来自当前官方资料并注明版本或日期？证据不足时标记待核实。

## 3. 教学因果链

对每个重要新概念追问：

1. 此前遇到了什么具体问题？
2. 已有方法为什么不够？
3. 因此需要什么能力或机制？
4. 概念名称是否在机制可理解之后出现？

若只能找到定义而找不到前三项，说明概念引入突兀。检查每一节开头是否回答“为什么现在讲这个”，每一节结尾是否为下一步留下真实问题。避免“接下来介绍……”这类只表示顺序、不表示因果的过渡。

## 4. 例子、公式与图

- 例子是否先给可感知的输入、过程和结果，再命名抽象概念？
- 是否沿用一个主例子，每次只增加一个条件？若切换例子，是否说明切换原因？
- 公式前是否先说它解决什么问题；每次代入、展开、取对数或求导是否解释这一步的目的？
- 数学推导是否既没有跳过关键等式，也没有用大量初等步骤淹没主线？
- 复杂的流程、对应关系或多步计算是否适合用图？图后是否有一句话指出读图重点？
- 图能否由正文独立解释，正文也不依赖图中未定义的信息？

## 5. 认知负荷与行文

- 一段是否只推进一个中心关系，但相关句子仍保持连续，没有拆成大量短句？
- 抽象术语或缩写连续出现前，读者是否先看到了可判断的现象、对比或失败？若没有，优先补充服务于机制的认知任务，而不是加入装饰性故事、口号或无关互动。
- 是否存在孤立事实、重复目标、空泛铺垫、无作用的总结或过多作者话术？
- 关键结论是否适量加粗，而不是整段加粗？
- 技术术语是否保持一致？不要仅为避免重复而换同义词，使读者误以为是新概念。
- 长句是否真的承载一个连续推理；若包含多个无关判断再拆分。不要把固定字数当作机械标准。

## 6. 重复与章节边界

逐项比较章内各节、前后相邻章节，以及正文、图、卡片和自测：

- 先标记每个内容块的主要用途，例如导航、推导、比较、应用、回忆或测验。主题相同不等于无效重复；只有结论、理由和用途都相同，且没有增加新条件或新判断时，才应合并或删除。
- 开头概览表或流程图若能帮助读者定位多个阶段，可以保留，但应只呈现现象与方向；正文必须解释概览没有展开的原因和机制。不要因为正文会详细讲解就机械删除导航，也不要在正文标题、段落和总结中逐项复述导航内容。
- 两处是否在回答同一个问题，并给出相同结论和相同理由？若后一处没有增加新条件、新关系、新例子用途或新的应用判断，属于无效重复。
- 本章是否重新展开了上一章已经建立的机制？需要承接时，用一两句指出“沿用什么、现在新增什么”，不要再次铺开完整定义、流程和例子。
- 同一风险或边界是否分散在多个小节反复出现？若它们服务同一个诊断问题，合并为一条完整链路、表格或决策图。
- 图是否只是把紧邻段落逐字换成节点？总结段是否只是重述开头和各节结论？若没有帮助读者建立新关系，应缩短或删除。
- 助记卡是否只承担回忆，自测是否要求解释、辨析或应用？若正文、卡片和自测只是相同问答的三次改写，应减少重复题或提高自测层次。
- 全景复习、螺旋复习和前情回顾是否确有新任务，例如跨章比较、故障定位或方案选择？这类必要重复可以保留，但应突出新组织关系，不重新教授全部细节。

完成去重后反向检查：被删内容中的前提是否仍在首次使用前出现；章节能否独立完成自己的核心推理；相邻章节的职责边界是否更清楚。不要用机械词频或相似句检测替代语义判断。

## 7. 学习闭环

- 助记卡是否一张只测试一个概念，问题保留成立前提，答案短而准确？
- 自测是否覆盖解释、辨析、场景判断和必要计算，而不是逐字复制卡片？
- 每道题是否能仅凭正文作答？参考答案是否给出结论和必要理由，没有新增知识？
- 题目、答案、正文修改后是否同步；链接是否指向正确文件？
- 资料已生成、用户已阅读、用户已掌握是否被严格区分？只有证据支持时才更新学习状态。

## 8. Markdown 与交付

- 标题层级是否连续，列表和标题前后是否留有规范空行？
- 标题、图题、表头、列表引导句和链接文字单独阅读时，是否准确且与正文术语一致？
- 段落、列表、表格、图、引用块和强调是否各自承担合适的信息关系，还是只为了视觉变化？
- 是否存在连续极短段落、过长列表、宽表格、大面积加粗或孤立公式？这些应作为风险信号人工判断，不按字数机械修改。
- 是否避免目标预览器不支持的 HTML 折叠标签和 LaTeX 定界符？
- 表格是否只用于真正的对应或比较，窄屏仍可理解？
- 内部链接与图片是否存在；Mermaid 是否语法简洁、节点文字可读？
- 作者检查、课时预算和验收矩阵是否放在规定位置，没有打断正文？
- 是否保留原始资料、用户答案和笔记，并更新入口、进度及相关引用？

## 最终判定

完成审查前，回答三个问题：

1. 学习者能否复述本章解决的问题和核心机制？
2. 学习者最可能在哪一步产生错误理解，资料是否已经在那里提供支撑？
3. 删除任何一段后，主线会不会断；保留任何一段是否只是因为“看起来完整”？

报告只保留有证据、可定位、可行动的问题，并优先列出最能提升理解的少数改动。

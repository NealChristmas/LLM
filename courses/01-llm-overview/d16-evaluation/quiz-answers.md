# D16 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是用可复现的证据同时评价质量、性能和系统组件。

1. 单题不能代表真实问题分布，也没有覆盖歧义、权限、失败与高负载。应加入常见任务、边界输入、工具异常、安全风险和历史故障等类别，并保留独立测试部分。
2. 正确含义可能有多种措辞，精确匹配会把合理改写判错。可建立包含事实正确、完整、忠于资料等维度的 Rubric，再由人工或经过人工样本校准的模型评分。
3. 最终失败只说明端到端目标未完成，不能指出原因。组件评测可以区分没找到证据、模型参数生成错误、权限正确拒绝、外部服务失败或副作用重复，从而选择正确修复层。
4. 多数普通请求可能更快，但少数边界或高负载请求变得更慢，尾部体验恶化。应在记录相同模型、硬件和负载条件的前提下，按输入长度、并发和场景继续切分，而不能只看平均值。
5. 不能直接宣布。优化提高了系统总处理量，却可能牺牲单用户等待；是否可接受取决于服务目标，还要同时确认质量、TPOT、成本和尾部延迟。成本与吞吐也应在相近质量和成功率下比较。
6. 多个变量同时改变，无法判断提升来自哪项，也无法知道某项是否退化后被另一项掩盖。应在一致条件下做单变量或经过设计的对照实验。
7. 这是高风险副作用错误，总体成功率可能掩盖它。加入回归集能防止再次发生，独立门槛可保证即使平均指标提高也不会放行重复创建。
8. 还要用自己的任务分布、语言、Prompt、上下文长度、RAG与工具链，在目标硬件和并发下测质量、延迟、吞吐、成本和风险边界，并记录完整版本与配置。

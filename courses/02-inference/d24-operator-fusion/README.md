# D24：算子融合为什么可能提升速度？

D18 看到 Transformer 会连续启动很多 Kernel，D19 又看到中间结果常写回显存。若两个相邻运算很简单，却在它们之间完整落盘再读回，搬运和启动开销可能超过计算本身。

## 1. 先看两个相邻的小算子

假设算子 A 生成中间张量 Z，算子 B 立刻读取 Z 并产生结果 Y。分开执行时，A 读取输入、计算并把 Z 写入显存；B 再从显存读取 Z、计算并写出 Y。如果 Z 只供 B 使用，完整写回再读回就可能是可避免的往返。

**算子融合（operator fusion）**把多个相邻运算放进一个更大的 Kernel，使中间数据尽量停留在寄存器或片上存储中，并减少 Kernel 启动次数。

```mermaid
flowchart TB
    subgraph before["未融合"]
        A1["Kernel A"] --> Z1["Z 写入显存"] --> A2["Kernel B 重新读取"]
    end
    subgraph after["融合后"]
        B1["融合 Kernel：A"] --> Z2["Z 留在片上"] --> B2["同一 Kernel：B"]
    end
```

## 2. 融合减少了哪几类成本？

第一类是中间张量的显存读写；第二类是 CPU 或运行时启动 Kernel 的固定开销；第三类是多个 Kernel 之间的同步。对于归一化、偏置、激活函数、残差相加等相邻操作，单个操作计算量不大，这些固定成本尤其显眼。

矩阵乘法本身也常把偏置或激活函数作为尾部处理合入同一实现，这类在主运算后紧接的小操作常称为 epilogue。名称不重要，核心是避免把刚算出的数据无谓地送远再取回。

## 3. 为什么不能把整层全部融合？

融合后的 Kernel 要同时保存更多中间数据，可能增加寄存器和片上存储压力。若每个线程需要太多寄存器，同时驻留的线程块会减少，GPU 并行度反而下降。某些运算还有复杂的数据依赖、不同的最佳切分方式或跨 Kernel 同步需求，强行融合会使实现低效。

此外，通用融合要支持多种形状和模型，而专用融合可以针对固定结构优化。越专用，潜在性能越高，但适用范围、维护成本和编译时间也可能更受限制。

## 4. 融合与计算图是什么关系？

模型前向过程可以表示为运算节点及依赖边组成的**计算图（computation graph）**。后端在不改变数学语义的前提下识别可合并模式，再选择融合 Kernel。动态图中的输入形状和控制路径若频繁变化，复用已优化执行计划会更困难；形状较稳定时，更容易缓存或捕获重复执行序列。

融合必须保持数值和依赖关系正确。浮点运算顺序变化可能产生细小舍入差异，因此仍需做输出一致性与质量验证。

## 5. 融合在哪些场景收益更明显？

| 场景 | 原因 |
| --- | --- |
| 多个相邻逐元素小算子 | 计算少，启动和中间读写占比大 |
| 中间张量很大且只被下一步使用 | 避免一次完整写回和重读 |
| 小批次 Decode 的许多短 Kernel | 单次工作少，固定启动开销更突出 |
| 已有成熟专用融合实现 | 能兼顾片上资源与并行度 |

若主耗时是一个已经高度优化的大矩阵乘法，融合外围小操作可能只有有限收益。仍应通过 D22 的方法确认热点，而不是按“融合越多越快”做判断。

## 6. 接到注意力优化

算子融合解决的是相邻步骤之间的往返，但标准注意力还有更大的中间矩阵：每个 Query 与所有 Key 的分数。长序列下，这个矩阵的读写会迅速增长。D25 将解释 FlashAttention 怎样通过分块和在线归一化避免把完整注意力分数矩阵写回显存。

## 助记卡片

**卡片 1：算子融合主要减少什么？**

> **答案：** 减少 Kernel 启动、同步以及中间张量写入显存后又读回的开销。

**卡片 2：融合后中间数据尽量保留在哪里？**

> **答案：** 寄存器、共享存储等更靠近计算单元的片上空间。

**卡片 3：为什么小算子更容易受益？**

> **答案：** 它们本身计算少，固定启动与数据搬运成本占比更大。

**卡片 4：为什么不是融合越多越好？**

> **答案：** 过度融合会增加寄存器和片上空间压力，降低并行度，也可能遇到不兼容的数据依赖。

**卡片 5：计算图提供了什么？**

> **答案：** 它明确运算节点和依赖，帮助后端判断哪些相邻步骤可以在保持语义时合并。

**卡片 6：融合为什么仍需正确性验证？**

> **答案：** 实现和浮点运算顺序可能改变，需要确认输出误差与模型质量仍可接受。

**卡片 7：融合前为什么先定位热点？**

> **答案：** 若主要耗时不在这些中间读写和小 Kernel，融合带来的总体收益会有限。

# 测算结果图规范

## 何时生成、放在哪里

完成本轮测算后，除客户正文及依据附录外，生成一张解释本次计算过程与选型结果的流程图，放在客户 Markdown 第三章末尾、第四章之前。它补充第三章的数值过程，不替代第二章不带数字的计算规则。未完成测算时不得绘制有确定卡数结论的最终图。

交付默认包含正文同目录下的 `sizing-flow.svg` 和可编辑图源（SVG本身可作为图源，生成脚本一并保留）。正文用相对链接嵌入：

```markdown
![本次模型推理算力测算流程图](sizing-flow.svg)

[查看流程大图](sizing-flow.svg)
```

优先采用无需安装依赖的矢量绘图；如交付端不能显示 SVG，则使用已有渲染工具导出 PNG 并嵌入，保留矢量图源。不要只给依赖特定渲染器的 Mermaid 代码块。仅改图时复用已有结果，不重新下载模型资料或运行完整测算。

## 信息组织

沿用[已确认示例](../assets/sizing-flow.example.md)的“顶部输入、分支计算、约束判断、底部汇总”结构，根据当次模型与部署调整分支：

1. **输入需求与部署条件**：模型、精度、长度及统计口径、规划并发、延迟目标、完整部署组、物理卡/Device单位。仅保留影响后续判断的条件。
2. **理论分支**：显存、输入阶段和生成阶段。显存显示权重、缓存、运行预留及逐设备容量比较；输入/生成各显示关键工作量、有效能力、实际调度模型及目标比较。PD 分离须保留两侧边界；特殊缓存不能画成普通KV公式。
3. **理论选组**：说明较小配置未满足哪项约束、候选配置为何可行。每个数字取自同一次结果，不能为排版重新手算或更改舍入后的结论。
4. **基线独立分支**：记录ID、每组卡数、达标或可参考并发、延迟口径、完整组取整。理论结果不作为基线输入；存在负载或配置差异时，公式旁标“条件参考”及其成立条件。
5. **综合汇总**：注明采用哪类结果以及另一类依据的作用，不取平均、不机械取最大值。分别显示工作组、工作卡、备用组、备用卡和总卡数；备用不参与日常工作能力预算。

图中的公式与必要数字来自本轮算法和结构化结果，关键系数注明实测、官方推导或预算假设。若使用效率折算，应标明其并非监控利用率。近似时延不能画成实测达标；基线和理论数量一致不能画成双重验证通过。模拟数据必须在图标题或顶部醒目标注。

## 版式与检查

白底、浅蓝圆角节点、蓝色正文、灰色箭头；限制/条件用浅黄色，底部预算候选用浅绿色。每个节点承载一个计算动作，通常3～6行；分支对齐，箭头不穿文字，中文与英文/数字适当留空格，单位和运算符清楚。图较宽时提供原图链接，不靠缩小字号塞入全部张量明细。

生成后检查：图中文字与正文/结果一致，数值与单位正确，箭头表达依赖而非时间先后误导，工作/备用边界明确，本地图片链接有效。解析SVG或检查图源语法，并用可用的本地图像/浏览器工具检查裁切、重叠和字体；无法做视觉检查时如实记录，不将语法检查称为视觉验收。验证绘图不需要重新做硬件性能测算。

## 示例的适用范围

示例保留一次真实用户基线配合授权工程假设的粗估结果，**不是模拟实测，也不是实测达标方案**。其中输入40%、生成2%等是未经实测校准的预算假设，48张是该案例预算候选；这些值不能成为新项目默认值。复用结构和表现方式，不复用模型算法、参数或卡数。

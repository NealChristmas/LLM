# 写作与教学设计参考依据

查阅日期：2026-09-14。以下是已阅读的一手资料，不是整套课程的转载。采用方式为针对当前学习者的设计判断，不代表这些来源直接验证了本学习计划的效果。

| 来源 | 采用的原则 | 在本资料库中的应用 |
| --- | --- | --- |
| [Google Technical Writing：Audience](https://developers.google.com/tech-writing/one/audience) | 根据读者已有知识与目标选择解释深度，避免默认读者懂术语 | 显式列出前置知识；不把软件工程经验等同于机器学习基础 |
| [Google Technical Writing：Documents](https://developers.google.com/tech-writing/one/documents) | 清楚界定范围，把关键点放在前面 | 开篇说明本课要解决的问题及学习目标 |
| [Google：Paragraph structure](https://developers.google.com/style/paragraph-structure) | 每段围绕一个意思，便于阅读 | 用连续解释建立因果关系，避免大段术语堆积 |
| [Diátaxis](https://diataxis.fr/) | 区分教程、操作指南、参考与解释四种文档需要 | 讲义组织学习路线；长篇原理和参数参考另页链接，排障按具体任务组织 |
| [The Carpentries：Designing Exercises](https://carpentries.github.io/lesson-development-training/instructor/formative-assessment.html) | 练习对应学习目标，在学习中检查理解并反馈 | 先定目标与验收题，再写讲解；每个关键知识块安排预测、解释或纠错题 |
| [IES / WWC：Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) | 间隔学习、示例与解题交替、图文结合、联系抽象与具体、提取练习及解释性问题 | 完整示例后给变式题；闭卷回忆后提供反馈；后续课时重访关键概念 |

IES 指南发布于 2007 年，各项建议的证据强度不同，也并非专门研究成人大模型自学。此处借鉴教学原则，不声称特定复习间隔或每日课时分配是唯一最优方案。

本项目自行决定的事项：每天 4 小时的分配、约 17 天的第一轮路线、每课目标数量、文件结构和复习时间。这些会根据用户实际完成时间及错误类型调整。

后续每课还需补充与该课技术内容相关的官方文档、原始论文或权威教材；本页的教学来源不能代替技术事实核验。

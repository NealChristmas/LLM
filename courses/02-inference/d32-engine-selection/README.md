# D32：vLLM、SGLang 与 TensorRT-LLM 应该怎样选择？

D31 已经确定选型必须从模型、硬件、负载和服务目标出发。本章不做永久排行榜，因为引擎功能与性能快速变化；这里只建立稳定的选型方法，并用截至 **2026-09-16** 的官方文档说明三者当前定位。

## 1. 先排除“哪个引擎最快”这个问题

一个引擎可能在特定 GPU、模型、精度、输入输出长度和并发下领先，换一个条件结论就会改变。若目标模型不受支持、部署硬件不同或缺少所需功能，公开榜单上的峰值没有决策意义。

更可靠的顺序是：先检查硬约束，再比较目标负载。

```mermaid
flowchart LR
    A["模型与硬件能否支持"] --> B["所需功能能否支持"]
    B --> C["运维与集成成本是否接受"]
    C --> D["目标负载下公平压测"]
    D --> E["质量、延迟、吞吐、成本联合选择"]
```

## 2. 三类定位怎样理解？

根据当前官方文档，可以先形成以下定位，而不是把它当成绝对边界。

| 引擎 | 当前定位重点 | 选型时优先确认 |
| --- | --- | --- |
| vLLM | 通用模型服务、广泛模型与硬件支持、PagedAttention、连续批处理及多种优化 | 目标模型/硬件支持、易用性、分布式与服务功能是否满足 |
| SGLang | 高性能服务与结构化生成生态，强调前缀复用、推测解码及复杂生成工作负载 | 工作负载是否有大量共享前缀、Agent/结构化生成需求与对应后端支持 |
| TensorRT-LLM | 面向 NVIDIA GPU 的深度优化库与运行时，提供量化、in-flight batching、分页缓存和多 GPU 能力 | NVIDIA 硬件与模型组合、构建/调优复杂度、所需精度和功能支持矩阵 |

三者都在快速吸收相似能力，例如连续批处理、量化、推测解码和分布式推理。因此“某功能只有某引擎有”很容易过时，应回到目标版本的官方支持矩阵。

## 3. vLLM 适合解决什么问题？

vLLM 官方文档强调高吞吐服务、PagedAttention、连续批处理、Chunked Prefill、前缀缓存、量化、推测解码，以及多种并行方式；同时提供常见 API 服务能力并覆盖多种硬件后端。它常适合希望较快接入广泛模型、建立通用服务基线的场景。

但“支持某种量化”不等于目标模型、目标 GPU 和目标并行配置的组合都受支持。具体选择仍需核对当前模型列表、量化限制和分布式说明，并在自己的负载上测量。

## 4. SGLang 适合解决什么问题？

SGLang 面向模型服务和复杂生成工作负载，其生态关注前缀缓存、结构化生成、推测解码、并行与 Prefill/Decode 解耦等能力。若应用包含重复系统提示、多轮 Agent、结构化约束或需要细致控制生成过程，可以重点验证它是否在目标模型上带来收益。

同样不能仅凭“Agent 更适合”下结论。共享前缀比例低时，前缀复用价值会下降；功能支持、模型兼容和运维习惯仍要逐项确认。

## 5. TensorRT-LLM 适合解决什么问题？

TensorRT-LLM 是 NVIDIA 面向 NVIDIA GPU 的开源推理优化库。当前官方文档列出量化、in-flight batching、Chunked Context、KV Cache 复用、推测采样以及多 GPU/多节点等能力，并提供针对 NVIDIA 架构的优化路径。它适合硬件栈明确为 NVIDIA、愿意为目标模型和精度做更深优化的场景。

代价是选型更依赖 GPU 架构、模型—功能支持矩阵、构建产物和调优流程。若团队更重视快速迭代与广泛模型切换，这些集成成本也必须计入，而不能只看最快的一次基准。

## 6. 怎样做最终对比？

为三个候选使用相同模型版本、精度、硬件、输入输出分布、到达率和停止条件。先验证输出质量与功能正确，再比较 P50/P95/P99 TTFT、TPOT、完成率、可持续吞吐、峰值显存和单位请求成本。若配置不等价，例如一个启用了量化、另一个使用全精度，结论必须明确写出差异。

还要记录非性能条件：部署和升级复杂度、故障诊断、监控指标、社区与供应商支持、许可证及团队熟悉度。**最佳引擎不是某项峰值最高者，而是在目标约束下总体风险和成本最合适者。**

官方资料入口（核对日期：2026-09-16）：[vLLM 文档](https://docs.vllm.ai/en/stable/)、[SGLang 文档](https://docs.sglang.ai/)、[TensorRT-LLM 文档](https://nvidia.github.io/TensorRT-LLM/)。这些链接用于核对易变支持情况，正文已经给出完整选型逻辑。

## 7. 推理原理阶段怎样收束？

D18～D22 建立 GPU 与性能诊断，D23～D27解释单项优化，D28～D31说明引擎怎样管理请求。D32 将它们合成一个选择原则：先明确负载与约束，再检查支持，最后用公平测试决定。下一阶段应进入实操，用一个固定模型建立基线、部署候选引擎并验证这些判断，而不是继续堆叠术语。

## 助记卡片

**卡片 1：为什么不能直接问哪个引擎最快？**

> **答案：** 性能依赖模型、硬件、精度、长度、并发和配置，脱离条件的排名无法用于具体决策。

**卡片 2：引擎选型的第一个门槛是什么？**

> **答案：** 目标模型、硬件、精度和必要功能的组合是否受支持。

**卡片 3：vLLM 的常见定位是什么？**

> **答案：** 面向广泛模型和硬件的通用高吞吐推理与服务，并提供分页缓存、连续批处理等能力。

**卡片 4：SGLang 选型时常重点验证什么？**

> **答案：** 共享前缀、复杂或结构化生成、Agent 工作负载及相关优化在目标模型上的实际收益。

**卡片 5：TensorRT-LLM 的硬件边界是什么？**

> **答案：** 它面向 NVIDIA GPU 做深度优化，选型需核对具体 GPU、模型、精度和功能支持矩阵。

**卡片 6：公平压测需要保持哪些条件一致？**

> **答案：** 模型与精度、硬件、输入输出分布、到达方式、停止条件和质量要求。

**卡片 7：为什么还要比较非性能条件？**

> **答案：** 部署升级、监控诊断、兼容性和团队维护成本会决定生产系统的总体风险。

**卡片 8：最终选择原则是什么？**

> **答案：** 在满足功能和质量的前提下，以目标负载的延迟、吞吐、显存、成本与运维风险联合选择。

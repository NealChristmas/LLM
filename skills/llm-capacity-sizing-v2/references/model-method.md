# 模型与部署专属理论算法

先记录模型仓库修订、config摘要、权重量化、缓存格式、框架版本、并行/卸载布局和卡内资源映射。形成“对象→算法→输入及单位→来源→适用条件→未覆盖项”的计划。

| 对象 | 必须识别与处理 |
| --- | --- |
| 权重驻留 | Dense/MoE、草稿/视觉/共享模块、混合量化、尺度/零点/填充、TP/EP切分与DP复制、共享/卸载。按张量分组到卡，主机预算单列；普通参数量×字节数只适用于简单统一格式。 |
| 缓存 | MHA/GQA、MLA、滑窗、压缩/共享来源、索引、草稿、页池和分配规则。共享去重、跨卡复制计入；固定状态不强行折成线性每Token值。不能只把C16总量减半当INT8。 |
| Prefill工作量 | 真实执行层、路由专家和注意力/压缩。2×阶段激活参数只近似线性层，激活参数不是运算次数。 |
| Decode工作量 | 自回归访存、注意力、路由和草稿/验证。分别记录生成工作Token与最终输出Token，接受率未知时不计加速。 |
| 运行与通信 | 激活、图、工作区、通信峰值、KV传输、主机卸载、带宽与排队。余量不能当严格上界；不要与预分配缓存重复计。 |

负载按同批突发、闭环或持续到达分别选调度模型。平均TTFT不等于全部请求完成时间；最繁忙Decode实例步长只是平均TPOT的预算近似。均衡逐请求先到先服务必须经用户确认，不能套实际连续批处理。

辅助脚本能计算平均完成序号、线性工作量、算力折算和容量算术，但不能识别架构。工具不足且依据充分时补写模型适配器并用手算边界验证，不能强塞通用KV。峰值与工作量精度必须对应，FLOP/TOP单位与乘加计数约定明确。未知用null，不用0。

多布局搜索：每个候选分别重算实例资源、权重分片、复制、共享、主机资源、缓存和时延；只有同时满足声明约束者可进入候选。未建模通信等条件时必须标成条件候选。备用不计入日常可用工作能力。不要把“最小完整组”写成“全局最小卡数”。

同版本官方资料固定摘要后复用，改变业务负载不重复下载。固定DeepSeek V4.1示例的80亿/160亿、A3卡数、效率、INT8假想格式都不是新项目默认值。

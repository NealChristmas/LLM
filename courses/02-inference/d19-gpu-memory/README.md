# D19：GPU 为什么需要多层存储？

D18 看到 Kernel 要先读取数据再计算。如果每次都从容量最大的显存读取所有数据，计算单元常常会等待。为缩短常用数据的距离，GPU 形成了容量、速度和共享范围不同的存储层级。

## 1. 先看一次反复使用权重小块的计算

计算矩阵乘法时，一个权重元素往往会参与多次乘加。若线程每使用一次都重新从显存读取，搬运次数会非常多。更合理的办法是把一小块数据取到离计算单元更近的位置，反复使用后再换下一块。由此产生了**存储层级（memory hierarchy）**：越靠近计算单元通常越快、容量越小；越远通常容量越大、访问越慢。

```mermaid

    A["主机内存<br/>容量大，跨总线"] --> B["GPU 显存 HBM/GDDR<br/>存放权重与大张量"]
    B --> C["L2 Cache<br/>多个计算单元共享"]
    C --> D["片上共享存储 / L1"]
    D --> E["寄存器<br/>线程当前数据"]
    E --> F["计算单元"]
```

这张图表示一般的数据距离关系，不代表每次访问都必须人工逐层搬运，也不表示所有 GPU 的具体结构完全相同。

## 2. 容量与带宽分别回答什么？

**容量**回答“能不能放得下”。若模型权重、KV Cache、临时工作区和激活值总和超过显存容量，服务就无法按当前配置运行。**带宽**回答“单位时间能搬多少数据”。即使数据能放下，如果每一步必须读取大量权重和缓存，计算单元仍可能等待搬运。

例如一张卡有足够空间放下模型，并不等于 Decode 一定快。Decode 每生成一个 Token 都要读取模型权重，并访问已有 KV Cache；当单步可并行计算不多时，显存带宽可能比峰值算力更先成为限制。

## 3. 为什么缓存能加速，但不能无限大？

缓存保留近期或反复使用的数据，使后续访问不必总去更远的存储。问题在于高速片上空间很小，只能保留工作集的一部分。当工作集超过缓存，旧数据会被替换，之后再用时仍需从显存读取。这种“某份数据能否在较近位置被再次使用”称为**数据复用**问题。

矩阵乘法 Kernel 会把矩阵分块，让一块 X 和 W 在片上被多次使用。好的分块提高复用；不合适的分块可能浪费片上空间，或者仍产生大量重复读取。推理框架选择 Kernel 时，实际上也在选择数据怎样布局、分块和移动。

## 4. 主机与 GPU 之间为什么也可能成为瓶颈？

CPU 的主机内存与 GPU 显存是不同的存储区域，数据通常要经过 PCIe 或其他互连传输。若权重频繁在两者之间换入换出，或请求预处理无法及时供给 GPU，GPU 会出现等待。把部分权重或 KV Cache 放到主机内存称为 **Offload（卸载）**，它可以缓解显存容量不足，却把问题转化为更慢的跨设备搬运。

**Offload 主要扩展可用容量，不等于免费增加显存。**只有当访问频率、传输带宽和计算重叠方式允许时，它才可能在可接受延迟内工作。

## 5. 推理时显存里有哪些主要内容？

| 内容 | 生命周期 | 主要受什么影响 |
| --- | --- | --- |
| 模型权重 | 模型加载后长期存在 | 参数量与权重精度 |
| KV Cache | 随活动请求和序列增长 | 层数、KV 头、头维度、长度、并发与数据类型 |
| 激活与临时结果 | 某些算子或层执行期间存在 | 批次 Token 数、隐藏维度与实现方式 |
| 工作区与运行时开销 | 由 Kernel 和框架使用 | 后端、算法、图捕获及内存池策略 |

D14 已解释这些对象的语义，本章新增的判断是：它们不仅竞争容量，也会产生不同的读取模式。权重长期存在但会被反复读取；KV Cache 随请求增长；临时结果寿命短，却可能造成高频读写。

## 6. 接回性能问题

当服务慢时，不能只看“显存使用率还有多少”。容量富余只能说明放得下，不能说明带宽未饱和；GPU 利用率高也不能自动说明计算单元在做最有效的工作。D20 将用“每搬一个字节做了多少计算”把计算限制与带宽限制区分开。

## 助记卡片

**卡片 1：GPU 为什么不只使用一种存储？**

> **答案：** 大容量存储较远且较慢，小容量片上存储更快；分层可以兼顾容量与访问速度。

**卡片 2：显存容量回答什么问题？**

> **答案：** 权重、KV Cache、激活和运行时空间能否同时放得下。

**卡片 3：显存带宽回答什么问题？**

> **答案：** 单位时间内能在显存与计算单元之间搬运多少数据。

**卡片 4：数据复用为什么重要？**

> **答案：** 同一数据在较近存储中多用几次，可以减少从较远显存重复读取。

**卡片 5：Offload 解决什么，又带来什么？**

> **答案：** 它用主机内存缓解 GPU 显存容量不足，但增加跨设备传输和潜在等待。

**卡片 6：显存未满为什么仍可能很慢？**

> **答案：** 剩余容量不代表数据搬运速度足够，瓶颈可能是带宽、计算或调度。

**卡片 7：Decode 为什么容易关注带宽？**

> **答案：** 每步新增计算规模较小，却仍需读取大量权重和不断增长的 KV Cache。

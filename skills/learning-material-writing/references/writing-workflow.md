# 完整章节写作流程

这个流程用于新建或大幅重写一章学习资料。它是作者的工作底稿，不要原样输出给学习者。

## 1. 画出最小推理链

先用不超过七个节点画出本章推理链：

```text
已知 → 具体困难 → 旧方法的缺口 → 新机制 → 机制如何运作 → 解释开篇现象 → 新边界
```

每个正文小节至少对应一个节点。不能对应的知识点先移到延伸内容，而不是强塞入主线。

## 2. 选择主例子

主例子应让读者不懂术语也能先看到问题，并能通过增加一个条件逐步承载后续概念。优先选小而可手算、输入输出明确的例子。不要在讲机制之前用现实系统的大量细节消耗注意力。

先验算例子的所有数值、维度和答案。教学简化必须明示，且不能导致相反结论。

当内容包含三个以上容易混淆的阶段、版本或路线时，可以在开头用小表格给出“可观察表现—尚缺能力”，让读者先获得导航。这个表格只负责预告现象和阅读方向；正文负责解释原因、机制与边界，不再逐行复述表格，也不必反复用“版本 A、版本 B”等标签重命名各节。若表格已经开始承担完整解释，就缩短表格；若正文只是在扩写单元格，就重新设计正文的推理任务。

## 3. 按需要引入概念

对每个新概念先写一句“没有它会失败在哪里”。这句话若无法建立，概念可能尚不该出现。

概念首次出现时：

- 在术语旁给出中文含义，必要时附英文；
- 立即指回它解决的具体困难；
- 只介绍当前推理需要的属性，其他属性留到真正用到时。

## 4. 处理公式和图

写公式时使用“目的 → 符号 → 推导 → 结果意义”的顺序。符号就近解释；只在符号多、关系复杂且会反复使用时列符号表。每行等式后检查读者是否知道“为什么要走这一步”。

在以下情况考虑画图：三步以上的流程、一个概念影响多个后续环节、层级或分支、多个对象间的精确映射。图后用短段落说明阅读方向和最重要的关系。

## 5. 组织段落

一段推进一个中心关系：首句承接上文的困难，中间用机制或例子解决，末句给出结论或留下下一步问题。相关句子保持连续，不拆成大量单句段。

删除不改变理解的开场白、重复目标、孤立事实和空泛总结。技术术语不用同义词换着说；只在主动语态真的能表明谁做了什么时才调整语态。

抽象概念或缩写连续出现时，先给读者一个可执行的认知任务，例如判断两个输出哪个更可靠、预测旧方法会在哪里失败，或比较一个条件改变前后的结果。任务必须直接服务于随后引出的机制，不添加与知识无关的故事或互动话术。

每节解决当前困难后，优先用主例子中仍未解决的真实问题过渡到下一节。不要在开头、节标题、段末和总结中反复宣告同一组阶段；概览负责定位，正文负责推导，结尾只有在建立新关系或提供判断方法时才总结。

## 6. 从正文反向生成练习

先列出正文真正建立的几个核心命题，再为它们选择回忆或应用形式。每道题标注其正文依据供作者自查，交付时可去掉该标注。

先独立写出参考答案，再检查：

- 答案是否和正文的符号、数值和限定条件一致；
- 题目是否只有一个预期理解，还是因为前提模糊出现多个合理答案；
- 答案是否借用了正文未建立的概念。

## 7. 终稿反向阅读

从结尾向前逐项追问：这个结论依赖什么，依赖项在首次需要前是否已经设立？然后正向通读，检查读者是否会在任何一节问“为什么突然讲这个”。

最后核对正文、图、卡片、题目、答案、导航和进度状态。若修改了核心例子或符号，搜索所有受影响的引用，不只修正当前段落。

# 大模型推理理论容量评估 V2

只做理论测算。输入是业务规格、模型config、同版本实现/参数清单、硬件与部署资料、必要预算假设。不要读取V1的性能基线文件、不要要求导入测试数据、不要用实测吞吐或历史卡数校准/反推参数。官方硬件规格和模型结构资料仍是必要依据；昇腾参考[硬件规格](references/hardware-specifications.md)，公开规格不等于实际有效能力。用户若需要实测匹配，说明需另用原版`llm-capacity-sizing`，本轮不自动切换。

## 工作流程

1. 复用已有明确版本的config、结构摘要和计算适配器，先识别本轮变化；仅查证不足部分，默认不下载权重、不执行远端代码。收集模型版本、模态、平均或其他统计口径的输入/输出长度、全部推理Token范围、峰值模型并发、TTFT/TPOT、负载方式、Prefix Cache、量化/缓存精度、硬件、框架、部署、增长和备用。缺失不从示例或历史结论补齐。
2. 默认开展[多布局比较](references/layout-comparison.md)，除非用户明确锁定布局或可核对证据只支持一种。围绕参考布局提出有结构依据的Prefill/Decode卡数组合，为每个候选重新核验权重、缓存、并行/卸载及请求调度，再比较资源与余量，不能线性缩放旧结果。只支持一种时先完成该布局预算，明确未完成多布局比较；必要时集中询问其余候选的依据。只能称“已评估候选集合内最少”，不能声称全局最少。
3. 按[模型适配规则](references/model-method.md)选择本模型的权重驻留、缓存、Prefill、Decode、通信及主机卸载算法。算法来自结构与实现，不固定所有模型的底层公式；工具缺适配由智能体补写并验证，不让用户提供理论JSON。
4. 通过必要证据检查后运行确定性本地脚本。通用算术辅助见[scripts/theory_math.py](scripts/theory_math.py)，它不是完整模型适配器；特殊缓存、PD与共享专家必须由适配器显式建模，不能因辅助函数可调用就默认假设成立。
5. 检查逐卡及卡内布局、时延、通信与主机条件，按完整部署配置取整；工作和备用分算。使用`scripts/compare_layouts.py`比较每个模型适配器实际重算的结果，区分不满足、计算缺项、条件候选和预算候选；固定比较同一组需求、假设场景与备用口径，保留未采用原因。只有用户授权粗估时才能采用明确假设，并展示敏感性，未知有效能力不擅自填写。输出区分理论下限、假设预算候选和未确定项，不声称实测达标。
6. 按[报告与绘图规范](references/deliverable.md)交付客户Markdown、依据附录、流程图和内部结构化结果。报告只读取同一次结果，修改排版只重渲染。没有基线核对、基线筛选或理论/实测综合章节。

## 证据与效率

配置不包含有效效率、通信、运行预留或全部部署细节。能自行查证的官方资料先核实并记录修订与摘要；真实必要缺项集中说明“缺什么、影响什么、可补什么”，询问并等待。用户明确无法提供且未授权调整范围后中止完整测算。已授权粗估的本轮假设不重复索要，但不能默认跨模型或新精度仍适用。

缓存精度/量化格式不受已有实现支持时，不能伪称可部署；若用户授权假想格式预算，明确数据布局、尺度与对齐假设，单列性能和质量未知项。计算验证与部署支持验证分开。只知道算力峰值时只给相应下限，不保证时延。

固定资料按修订和摘要复用，业务参数变化只重算依赖项；模型、量化、缓存或部署变化重新选择适配。不要每轮扫描全部权重文件头。保存源摘要、算法/脚本版本、输入单位和运行结果；不重用旧卡数。

## 固定表达要求

- 资源最小展示单位为物理卡，显存与算力按整卡列示，报告和图不出现Device；内部保留卡内分片检查，整卡容量不是共享显存池。
- 阶段称Prefill / Decode，不称输入侧/生成侧；请求分配单元称推理实例，不称进程或推理工作组。实例可跨卡、可共享专家，不等于独占完整权重副本。完整部署组另有含义。
- 计算规则不带本轮数字；测算过程先中文变量公式，再数值代入及结果，保持同一连续等式，不主动拆段。公式不确定时不因模板需要而编造。
- 仅理论结果不能因数值与历史方案相同而升级成实测证据。无备用时说明预算未配置额外冗余。

客户交付须区分需求与建模假设，解释关键显存数字的分片/复制来由，精简重复限制；按[报告与绘图规范](references/deliverable.md)将流程图置于最前并生成包含本地必要依据的独立交付包，校验移出仓库后仍可打开。

# D14 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是把显存组成与 Prefill、Decode 两个阶段联系起来。

1. 70 亿 × 2 字节约为 140 亿字节，即约 14 GB 十进制容量。实际还要容纳 KV Cache、临时激活、工作区和运行时开销，并为并发和长度峰值留空间。
2. 每生成一个新 Token，都要把越来越长的完整序列重新经过所有层，并再次计算历史 Token 的 Key、Value 等层内结果；历史越长，重复越多。KV Cache 保存每一层的历史 Key/Value，使新增 Token 只计算自己的 Query、Key、Value，再用新 Query 读取缓存。未来每个新 Query 都会继续使用历史 Key/Value，而旧 Query 已完成旧位置当时的查询，后续不再需要，所以通常不缓存历史 Query。缓存仍需关注历史内容，只是避免对历史位置做完整的重复前向计算。
3. Prefill 输入整段 Prompt，集中处理输入并建立初始 KV Cache，输出首个预测所需状态；Decode 每步接收已有缓存和最新 Token，计算下一个 Token 并把新 Key/Value 追加到缓存。
4. 长 Prompt 增加开始输出前必须完成的 Prefill 工作；长回答增加有前后依赖的 Decode 步数，所以会延长从首 Token 到结束的时间并持续扩大缓存。
5. 权重在低并发时已经相同。并发升高会同时保留更多请求的 KV Cache，也可能增加批处理临时空间，因此应检查缓存和峰值工作区，而不是只看权重。
6. GPU 可以并行完成一次模型前向中的大量矩阵运算，但自回归的第 n+1 个 Token 依赖第 n 个 Token，跨生成步骤仍有顺序依赖。
7. 不应只优化模型计算。GPU 空闲而用户等待可能来自请求排队、检索、工具调用、网络、限流或调度空洞，应先按端到端时间拆分定位。

第 1、2 题不清楚时回看第 1、2 节；第 3、4 题回看第 3、5 节；第 5～7 题回看第 4～6 节。

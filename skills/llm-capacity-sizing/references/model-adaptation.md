# 按模型与部署适配计算

固定理论→实测→综合的流程、单位、输入校核和取整规则。模型内部公式依据实际结构与部署选择，不能由模型名称、config字段是否齐全或报告模板决定。

## 1. 确认计算对象

适配身份包括模型仓库及提交、config摘要、实际权重量化、缓存实现/精度、推理框架及版本、模态、并行与卸载布局、物理卡/Device计量。相同config不意味着相同显存占用和计算路径。已有资料直接复用；缺少公开资料时先自行取得同版本官方说明、实现或张量索引，只读取，不执行远端代码。

形成简洁的计算方案，逐项写出“计算对象→采用算法→输入及单位→依据位置→适用条件→未覆盖项”。区分有证据的公式、经用户确认的预算假设与未知项，不为适配工具反向编造数值。

## 2. 选择模型内部算法

| 对象 | 需要识别的机制 | 计算方法的选择 |
| --- | --- | --- |
| 权重 | Dense/MoE、共享/草稿/视觉/条件记忆模块、混合量化 | 按实际张量形状与存储格式分组计数数据、尺度、零点、填充及复制；简单统一精度才可用参数数×每参数字节数 |
| 权重驻留 | TP/EP分片、DP复制、绑权重、CPU卸载 | 按设备与内存池映射张量，共享张量去重；主机内存和卡上显存分别预算 |
| 缓存 | MHA/GQA、MLA、滑窗、压缩、跨层共享、索引/草稿状态 | 据实现枚举缓存对象、形状、分配长度和副本范围；普通KV公式仅适用于已核对的标准结构 |
| 输入工作量 | 输入实际执行层、MoE路由、注意力/压缩/多模态计算 | 按输入计算图计数；2×相应激活参数只近似矩阵线性层，额外算子与长度相关工作单列 |
| 生成工作量 | 生成路径、注意力读写、草稿/验证、接受率 | 独立于输入计算；推测解码区分计算Token与最终输出Token，不默认接受率或加速比 |
| 运行显存 | 预分配池、分页、图捕获、激活/通信缓冲、临时峰值 | 按框架分配和阶段峰值预算，区分已用、已分配与物理上限，避免重复叠加预分配缓存 |

缓存按实际对象求和：同一内存池中的共享对象只计一次，跨设备复制分别计入；滑窗按保留窗口及分配规则计算，压缩按来源层和实际压缩对象计算。固定状态、索引及元数据不能统一折成每Token线性系数。只有相同对象、布局及元数据规则明确时才可按精度字节数调整，不能把原生FP4全局缓存预算直接倍乘成C16全部运行缓存。

参数量、激活参数量与运算量不同。官方激活参数不等于完整FLOP；索引total_size和打包元素数不等于逻辑参数量。参数数相同但计算图不同的模型不自动共用算法。

## 3. 从模型预算到部署约束

按用户负载确定请求怎样进入系统。并发、到达速率、长度分布和同时突发不同；不能统一套“并发×输入长度×每Token计算量÷TTFT”预测平均TTFT。输出长度影响缓存、请求时长及稳态负载，也不能仅凭输出总长度推断实时生成能力。

逐设备检查常驻权重、缓存和运行峰值，不能只看整组总显存或平均分配。共享资源才采用对应竞争模型；PD分离分别预算P/D阶段、KV传输、队列和卸载带宽。MoE的DP/TP/EP可能共享专家而复制非专家权重，不能将并行度乘积直接当完整副本数。

计算需求与峰值只形成相应近似下的理论下限。有效能力、带宽、通信及调度依据不齐，不能随意填效率得到确定卡数或声称均值/P95时延达标。候选按完整部署布局取整，工作和备用分开，基线核算独立进行。

## 4. 选择或补充数值工具

1. **已有匹配算法**：满足脚本全部前提才复用，记录算法与脚本版本。`sizing.py`的标准KV辅助解析与`theory-calculate`只覆盖声明的特例。
2. **缺少实现、依据充分**：智能体在本轮输出目录编写确定性的本地Python计算脚本，必要时扩展工具库；不让用户提供公式、理论JSON或替代工具。只用已核实输入，不执行下载的模型代码，不用eval运行动态公式。非必要不引入依赖。
3. **验证计算**：检查单位、输入/生成分算、共享与复制去重、物理卡/Device、逐设备及P/D约束。用可手算的小规模案例核对数值，用长度/并发或布局变化检查分支；有同版本实现/测量时再对照。未运行或假设未确认的结果如实标注，脚本运行不代表部署性能通过。
4. **接入结果**：保留输入摘要、算法/脚本摘要、公式、来源、条件和数值。新结果超出现有导入/报告格式时扩展解析与报告路径并验证；不能伪装成旧共享结果，把PD改名共享部署，或改导出数字绕过校验。
5. **真实依据缺失**：先自行查证公开部分，再集中询问必要现场材料或预算假设并等待。用户明确无法补充且不调整范围后才中止；实现工作与资料补充是两类问题。

现有Skill未内置覆盖所有模型的自动适配引擎，本流程规定智能体如何选择、补充和验证。编写前不声称架构已支持。可复用适配器验证后再纳入Skill，按版本/配置显式匹配，不按模型系列模糊套用。

## 5. 结果与交付

内部记录至少包含适配身份、阶段/设备/内存池、每项输入及单位和来源、公式/算法标识、条件、结果及单位、精确/近似/未知状态、未计入项、脚本与运行记录。未知结果用null或单独状态，不能用0占位；必要部分未知时不能把已算部分之和冒充完整预算。

客户Markdown沿用既定版式，主要关系放“计算规则”，数字放“测算过程”，架构细节与算法依据放附录。正文合并公式仍保留实际阶段与内存边界，不能为套模板删掉Engram、草稿缓存、卸载或PD阶段。

本次DeepSeek-V4.1-Flash的适配检查点：已核实资料中的输入/生成激活参数为8B/16B，须分别计算；890字节/Token原生全局缓存不能直接替代W8A8C16；Engram驻留位置和A3每物理卡两个Device须参与部署预算。这是本次版本的检查点，不是其他DeepSeek模型的默认值。

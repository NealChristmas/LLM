# D01～D17 阶段自测参考答案

1. 当前对话只改变这次请求的上下文，普通推理不会计算训练损失、反向传播梯度并更新参数。要形成长期参数变化，需要后续训练流程或外部记忆机制。
2. Tokenizer 将文字切成 Token 并映射为 Token ID；Embedding 与位置信息形成隐藏向量；隐藏向量依次经过多层 Attention、前馈网络、残差和归一化；最后位置的表示转成 Logit，经 Softmax 得到概率，再按生成策略选择首 Token。
3. Transformer 每层为序列中的每个位置输出一个新隐藏向量，数值含义会变化，但输出仍按相同位置排列。因此位置对应关系保留，不表示向量仍保存原 Token 的字面内容。
4. 优先使用 RAG。制度是频繁变化的外部私有知识，RAG 可以在每次请求时检索当前版本；微调更新慢，也不适合作为精确、及时的制度存储。若还需稳定改变回答风格或任务行为，才另行考虑微调。
5. 模型文本只是对动作的描述。真正提交必须由程序校验参数和权限、调用审批系统，并返回可验证的执行结果；模型也可能在未执行时生成“已提交”。
6. 会增加路径不可预测、循环不停止、错误动作、成本失控和调试困难。步骤固定时，显式工作流更容易验证、限制副作用并确定停止条件。
7. TTFT 还可能包含检索、工具或网络等上游耗时以及进入模型前的排队。必须先分段计时，才能判断主要时间是否在 Prefill。
8. 可能原因包括：原瓶颈不是权重带宽；硬件或后端缺少高效低比特 Kernel；反量化开销抵消收益；长上下文的 KV Cache 读取才是主要瓶颈。任选两个并说明即可。
9. 先检查正确证据是否被召回并进入上下文。若没有，是检索、切分、索引或重排问题；若证据正确完整但回答仍与证据不符，再检查上下文组织、提示指令和模型生成。
10. 先把“答案不准”与“响应慢”拆开。质量侧依次检查测试目标、输入资料、检索、上下文、模型生成和工具结果；性能侧拆分上游、排队、Prefill 与 Decode，再判断容量、调度或模型计算。定位后只改变对应层，并在相同测试集与负载下重新比较质量、延迟、吞吐和成本。

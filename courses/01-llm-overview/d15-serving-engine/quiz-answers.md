# D15 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是理解推理引擎怎样在显存、延迟和吞吐之间调度。

1. 批次成员的生成长度不同，短请求结束后，如果批次保持固定，其位置无法及时由新请求接替；新请求还要等最长请求结束，形成空洞和排队。
2. 调度器在每轮生成之间检查请求状态，让完成的请求退出，并把等待请求加入下一轮可运行批次，而不是等整个原批次结束。
3. 最大预留会让短请求占着大量未使用空间，不同长度还容易造成碎片。PagedAttention 把缓存拆成固定大小物理块，通过映射组成每个请求的逻辑连续缓存，并按需增加块。
4. 可以复用完全相同的系统提示词前缀所产生的缓存；不同的用户问题仍需 Prefill，之后的新 Token Decode 也不能因此全部省掉。
5. q=round(0.27/0.1)=round(2.7)=3，恢复值 x̂=0.1×3=0.3，因此误差为 0.03。大量权重的近似误差可能影响任务质量；实际速度还取决于硬件和算子是否高效支持该格式、是否需要额外转换，以及原瓶颈是否真的来自权重读取，所以质量和速度都要实测。
6. 系统可能等待或组合更大批次，使单位时间处理的总 Token 增多，但每个请求进入批次前等待更久。吞吐和单请求延迟是不同目标，出现取舍并不矛盾。
7. 瓶颈更可能在排队，因为 3.0 秒中有 2.2 秒消耗在等待调度，而 Prefill 只有 0.6 秒。缩短 Prompt 主要减少 Prefill，不能直接消除占比最大的排队时间，因此应先检查服务容量、连续批处理与调度策略。如果 TTFT 正常但 TPOT 很高，应检查 Decode 阶段的批次调度、模型规模、计算内核、显存带宽和 KV Cache 访问。

# D04 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是区分文本切分、索引、向量表示和位置信息各自的职责。

1. 完整句子的组合近乎无穷，为每句话分配编号会让词表无法控制。全部拆成单字符可以缩小词表，但常见词语会被拆散，Token 序列通常也会变长。Tokenizer 需要在词表规模和序列长度等因素之间折中。
2. **不能。** 这是本章明确定义的教学分词器。不同模型可能使用不同词表、规范化和切分规则，因此相同字符串可能产生不同 Token 序列。
3. **不能。** Token ID 只是词表索引，编号大小和 Token 的重要性、含义或相似度没有直接关系。它用于定位 Embedding 矩阵中的对应行。
4. Embedding 矩阵的形状是 **[V,d]=[5000,8]**。输入含 L=6 个 Token，查表后的向量序列形状是 **[L,d]=[6,8]**。
5. Embedding 矩阵参与模型计算，其数值会像其他参数一样根据损失和梯度更新。它不是人工给每个词填写的固定解释；训练会让这些向量形成对预测有用的关系，但单个维度通常不能直接解释成固定语义。
6. 两句话的 Token 种类相同但排列不同，表达的施动者和受动者相反。位置信息让模型能够区分 Token 所在位置及相对顺序，而不是把句子当成无序集合。
7. 顺序是：**字符串经 Tokenizer 切成 Token → Token 通过词表映射为 Token ID → ID 查询 Embedding 矩阵得到 Token 向量 → 向量结合位置信息形成可继续计算的序列表示。** Token ID 负责索引，Embedding 负责把离散 Token 映射为可学习的连续向量。

第 3 题不清楚时，回看正文第 2 节的“索引”类比；第 4、5 题不清楚时，回看第 3 节的 Embedding 矩阵；第 6 题不清楚时，回看第 4 节的顺序例子。

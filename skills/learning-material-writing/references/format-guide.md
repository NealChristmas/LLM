# Markdown 排版与信息层级

排版的目标是帮助读者快速识别“我在哪里、这块内容与上一块是什么关系、什么需要记住”。先服从项目规范和目标预览器，再使用下列通用原则。

## 先选内容块，再写内容

每一块内容只选择最能表达其关系的形式：

| 内容关系 | 优先形式 | 不要这样用 |
| --- | --- | --- |
| 连续的因果或推导 | 段落 | 把每句拆成列表或单句段 |
| 真正并列的条件或步骤 | 列表 | 用列表堆叠需要前后解释的观点 |
| 多对象的同字段比较 | 表格 | 把长段解释塞入单元格 |
| 流程、层级、分支或映射 | 图 | 用图重复一句话就能说清的事 |
| 短且必须注意的边界 | 就近的加粗句或少量引用块 | 每节都加“注意”告警框 |
| 公式、命令、代码或字面符号 | 对应的原生表示 | 为了显眼把普通文字放进代码块 |

当两种形式都能表达时，选更容易在当前屏幕和预览器上阅读的一种。

## 标题是导航，不是装饰

- 每份文档通常只有一个 H1；层级逐级递进，不从 H2 跳到 H4。
- 仅在读者需要在目录中定位新的内容单元时新增标题。短过渡不单独设标题。
- 标题直接说明该节要解决的局部问题或机制；只看标题就应能大致复原本章逻辑。
- 避免“背景”“核心概念”“深入理解”等无法区分内容的空标题，也不用口号、双关或表情符号增加“活泼感”。

## 空行与段落密度

- 标题、列表、表格、引用块和代码块与普通段落之间留一个空行，文件使用 UTF-8 并以换行结束。
- 空行表示思想切换，不用它把一条连续推理拆碎。相关的三到六句通常可以形成一个段落，但不以句数作为硬性阈值。
- 不为追求源码行宽而在中文段落中人工换行；交由预览器自动折行。只在语义换段或 Markdown 块边界换行。
- 避免不间断空格、Tab 和无意义的行尾双空格，它们在不同预览器中表现不一致。

## 列表、表格与强调

- 列表项必须处于同一逻辑层级，并使用一致的句式。带顺序或依赖的流程用有序列表，无顺序的并列项用无序列表。
- 列表前用一句话说清列表各项共同回答什么；列表后只在需要解释各项关系时补段落。
- 表格必须有可比较的稳定列。若单元格需要多句话或推导，改用小节或列表。表头用能独立理解的具体名称。
- 加粗只标记术语首次出现、关键因果或本段结论；不加粗整段，不在同一句中制造多个争夺注意力的重点。
- 行内代码只标记文件名、命令、API、标识符或必须逐字阅读的符号，不把普通术语包成代码。

## 公式、图和引用块

- 根据目标预览器选公式格式。如果 LaTeX 不稳定，使用原生 Markdown 可读的 Unicode 符号和上下标；不把公式放进代码块仅为了防止换行。
- 图中只保留理解关系必需的文字，避免把整段说明塞入节点。图后的说明要指出阅读顺序和核心关系，不逐节点复述。
- 引用块用于助记卡答案、真正需要与主线分离的边界或引文。普通解释不放进引用块，也不滥用 HTML 折叠标签和重型告警框。
- 所有图、表和代码块都需要就近的引导句；不让读者猜它为什么出现。

## 结构文字也要审稿

终稿时将正文暂时忽略，单独读一遍文档标题、各级标题、图表说明、列表引导句、链接文字和助记卡问题。它们应当准确描述所引导的内容，且术语与正文一致。

再进行一次纯视觉扫描：是否出现连续的极短段落、过长列表、宽表格、大面积加粗、孤立公式或连续告警块？这些只是风险信号，要回到内容关系决定是合并、改写还是保留，不按字数机械修改。

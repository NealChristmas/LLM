# 视频教材写作

把视频证据转为读者能独立理解的教程，而不是扩写时间轴摘要。默认交付 Markdown，必要图片保存在相邻目录。复用分析器已有输出；仅在关键事实缺失时请求补充证据，不重新下载整段视频。

## 从证据到讲解

1. 确认视频范围、读者前提和核心问题，区分字幕事实、画面事实、分析推断及外部补充。视频说得不完整时，不把猜测写成讲者结论；时间、身份或字幕来源的限制保留在来源说明中。
2. 重排为学习路径：先呈现具体困惑，再让例子暴露机制，随后推广到名称、公式与适用边界。不要直接采用视频时间轴或分析器条目作为章节目录。
3. 按内容选展开方式。**机制类**优先使用贯穿例子，展示输入、中间变化、输出，并用去掉或替换某一步的对照解释其必要性；**操作类**展示实际步骤、可观察结果及失败分支；**概念类**用对照情境解释边界。只在数字或代码能澄清机制时加入它们，不强制所有内容写算例。
4. 一个段落完成一段推理，每节承接上节留下的问题。先让读者理解发生了什么，再抽象成公式；变量与维度就近解释。避免用“提取特征”“提高表达能力”等宽泛词替代关键过程。
5. 用图解释正文难以直接看见的关系：中间状态、坐标对应、数据流或对照。截图证明画面内容，作者图解释机制，分别标明来源。读图须交代观察点及简化边界；没有解释作用的图可以不放。
6. 补足独立理解所必需的前提，优先核对原始论文或官方文档。新增例子、假设、简化与视频事实分开；任意权重产生的结果不能冒充训练模型输出，未运行的代码不写运行成功。
7. 核对关键计算、维度、图文一致性、局部路径与来源定位，然后修订交付。对于数学与算法教程，按 [机制讲解与复核](references/mechanism-review.md) 检查例子能否支撑结论。

## 成稿边界

- 不默认添加助记卡片、自测题、学习计划、课时预算或固定章数。不要从历史课程或其他写作 skill 继承这些附加模块；以当前任务的明确要求为准。
- 不限定字数和图片数量；篇幅用于补齐关键推理，删掉重复结论和无用铺垫。短视频可以配必要理论补充，但不能声称已经覆盖整门课。
- 正文以讲解为主，少量引用贴近补充事实；字幕编号与详细时间定位可集中在末尾来源表，避免打断阅读。
- 直接交付最终 Markdown 与必要图片。只在用户要求对比时提供候选稿与取舍记录，不默认产出网页、PDF 或额外审查报告。

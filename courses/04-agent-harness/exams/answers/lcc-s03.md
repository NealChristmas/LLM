# LCC s03 自测参考答案

这份答案从旧项目的逐章自测中继承。先完成[题目](../lcc-s03.md)，再核对。

1. 模型可能产出危险命令（`rm -rf /`）且不可控；安全要靠代码兜底。s03 在"工具执行前"插入 `check_permission()`。
2. ① 拒绝列表（硬拒绝）→ ② 规则匹配 → ③ 用户审批。顺序理由：最危险的先硬拦掉（不打扰用户），上下文相关的交给用户判断，都没问题就放行——兼顾安全与效率。
3. 闸门2 命中 → 暂停问用户（闸门3），用户 deny 则拒绝、allow 则继续。三道都没命中 → 直接执行。
4. 字符串匹配可被命令变体 / shell 展开绕过，例如 `rm -rf /` 加引号 / 空格变体、`sudo` 用拆分或变量展开（`s''udo`）等绕过字面匹配。不可靠 → 生产用多来源规则 + 真解析。
5. 缺 `passthrough`：工具自己不表态，交给通用管线决定（教学版没有"工具自己不表态"这一档）。
6. 不参与。`isDestructive` 纯 UI 展示用（工具列表标 `[destructive]`），不进权限决策；默认所有工具返回 false。

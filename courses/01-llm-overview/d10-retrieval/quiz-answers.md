# D10 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是把文档切分、表示、索引、召回和重排连接成一条检索链。

1. 按整篇文档检索会把大量无关内容连同相关段落一起返回，浪费上下文并干扰后续处理；切得极短又可能把条件、对象和结论拆开，使单个文本块失去完整含义。切分需要在主题聚焦与语义完整之间取舍。
2. 两种说法的准确词面重合较少，纯关键词匹配可能给相关段落低分。向量检索用 Embedding 模型分别编码问题和文本块，希望含义相近的表达得到方向接近的向量，再按相似度找回。
3. q·d=0.6，‖q‖=1，‖d‖=√(0.6²+0.8²)=1，所以余弦相似度为 0.6。它表示在这个向量模型和表示空间中方向有一定相似性，不保证文本一定包含正确答案，也不是事实正确率 60%。
4. 资料准备阶段执行文档切分、计算文本块向量并建立或更新索引；查询阶段收到用户问题后计算问题向量，再使用索引查找候选。前者通常在资料变化时运行，后者通常随每次查询运行。
5. 海量向量逐一精确比较会带来较高计算量和延迟。近似最近邻用可能漏掉少量真实近邻的代价换取更快搜索和更少资源，是否值得要看真实查询上的召回质量与性能。

7. “ERR-4821”需要精确字符串匹配，关键词检索通常更有优势；自然语言问题可能与制度使用不同措辞，向量检索更可能找出语义相近段落。混合检索可以同时利用精确词面和语义相似性，再对合并候选重排。

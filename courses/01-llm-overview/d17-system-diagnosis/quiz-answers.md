# D17 自测参考答案

先完成[正文末尾的自测](README.md)，再核对。答案重点是根据证据选择最直接的修复层，而不是背诵固定方案。

1. 大模型参数不会自动同步公司的最新制度，问题更可能来自源文档、版本过滤、索引更新或检索。应先确认现行制度是否进入资料库、被召回并实际送入上下文，再决定是否需要改生成层。
2. 正确知识已进入上下文，先检查 Prompt 是否明确格式并提供足够示例；如果在代表性案例上仍长期无法稳定形成所需行为，再评估更合适模型或微调。RAG 负责提供知识，不是稳定塑造格式的首选。
3. 主要属于工具执行、状态与幂等层，而不是模型选工具错误。应为同一逻辑请求使用稳定标识，执行端去重，并在超时后查询原请求状态而非盲目重试。
4. Prefill 本身没变而 TTFT 在高峰升高，优先检查服务层的排队、容量、批处理调度和限流，也要排除检索与网络等待。
5. 删除片段可能使正确证据不再进入上下文，造成质量或引用退化。必须在同一评测集上复测检索覆盖、回答质量和风险，再同时比较延迟收益。
6. 固定能触发超时的输入和系统版本；定义预期为“不得报告成功，应说明状态未知或安全查询”；查看工具返回与模型上下文，定位是否反馈结构或结果理解首先偏离；只修改该层；在原案例及其他成功、失败案例对照测试；最后把超时误报加入回归集。
7. 最新价格需要实时查询工具或可靠外部数据；长期输出风格不稳定先用清晰 Prompt，仍不稳定再评估微调；真正发送邮件必须使用受权限、确认和审计保护的工具调用。
8. D01～D08解释模型怎样计算、学习、处理文字并形成生成能力；D09～D11用上下文和 RAG提供本次请求及外部知识；D12～D13让程序执行真实动作并组织多步任务；D14～D15用硬件和推理引擎承载生成；D16～D17用质量、性能、轨迹和分层证据判断效果并选择改进层。

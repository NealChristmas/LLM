# “一份资料，怎样变成大模型真正能学习的数据？”自测参考答案

建议先独立作答，再检查是否遗漏了训练目标、数据单位或质量边界。

## 1. 原始 PDF 要经过哪些处理？

至少需要记录来源与许可，解析出正文并统一格式，过滤乱码和低质量内容，进行精确或近似去重，处理隐私与敏感信息，排除受保护的评测数据，再按来源配比、Tokenize、拼接和打乱。各项目会调整具体步骤，但不能把“下载完成”视为“可直接训练”。

## 2. 扫描书怎样变成训练序列？

先将纸质页面扫描成图像，再用 OCR 转成文字；随后识别章节和段落，清理页眉、页脚、页码、断行、乱码及 OCR 错误，并进行语言识别、去重、质量、许可和隐私检查。最后由 tokenizer 转成 Token ID，再按训练上下文长度切成多个序列，必要时将短文档拼接以减少空位，并保留文档边界。整本书往往超过一次训练可处理的上下文长度，所以不能一次输入，而是作为多个片段经过采样、打乱后分批训练。扫描、OCR 和批量清洗适合程序完成；人仍需确定来源与许可、制定规则，并抽检公式、表格、复杂版式和识别错误。

## 3. 语料是否专指未标注预训练文本？

不是。语料泛指为语言研究或训练收集的语言材料，可以是普通文本、对话、平行翻译或领域文档。它是否用于预训练、SFT 或其他任务，取决于后续加工和训练目标。

## 4. 为什么清洗后还要设计配比？

清洗只能判断样本是否达到最低可用标准，不能决定有限 Token 预算如何分配。代码、数学和网页比例会影响模型获得的训练信号；一种来源增加就会挤占其他来源，因此还要根据目标能力和小规模实验决定采样比例。

## 5. 7B 和 1T 分别描述什么？

7B 表示模型大约有 70 亿个可学习参数，1T Token 表示训练过程处理了约 1 万亿个文本 Token。参数是模型内部被更新并保存的数字，Token 是训练材料的计量单位，因此 7B 不能解释为模型只读过 70 亿个 Token。

## 6. 为什么 2 万个 Prompt 会低估 RL 规模？

2 万只统计起始问题。若每个 Prompt 生成 16 条回答，就会产生至少 32 万条 rollout；每条长回答还包含许多 Token，并可能在多个训练轮次重新采样。实际生成与处理量远大于静态 Prompt 数。

## 7. 为什么蒸馏输出仍需质检？

教师模型可能生成语法错误、使用不存在的字段或得到错误结果。执行验证可以检查 SQL 是否可运行及结果是否正确，去重避免大量近似样本挤占预算，人工抽检则能发现自动规则没有覆盖的语义错误和安全问题。

## 8. 为什么高分不能证明泛化？

模型可能记住了训练中出现的评测题和答案，而不是学会解决未见问题。此时测试集不再独立，高分会高估真实能力；需要使用隔离的新评测集或进行污染分析。

# 中文学习资料质量审查

目标是让学习者读完后能回答“为什么需要这个概念、它怎样工作、它与前后内容有什么关系”，而不只是让文字更顺。保留作者意图、技术含义和已有学习记录；没有依据时不要擅自改动事实或宣称学习者已经掌握。

## 确定范围和模式

先阅读完整目标文档及其直接依赖，包括项目级 `AGENTS.md`、写作规范、学习者背景、知识地图、前后章节、题目与答案。项目规范优先于本 Skill 的通用建议。

- 用户要求“审视、检查、评价”时使用**审查模式**：不修改正文，输出按影响排序的问题清单。
- 用户要求“优化、修改、重写”时使用**修订模式**：先完成审查，再直接修改授权范围内的文件并验证。
- 用户只指出一个局部问题时使用**定向模式**：检查该问题，同时追踪受它影响的卡片、题目、答案、导航和进度记录，避免无关重写。
- 若请求同时包含审查与修改，视为已授权修订，无须再次询问。

涉及一章或多章的完整审查时，必须读取 [审查清单](references/review-checklist.md)。仅做明确的排版机械检查时，可直接运行脚本而不加载清单全文。

## 工作方法

1. **建立上下文。** 明确学习者已有知识、当前阶段、文档要回答的问题，以及它在整体知识脉络中的位置。不能仅凭单篇文档猜测课程目标。
2. **先验事实，再验教学。** 核对公式、数值、术语、变量、图文和答案；再检查概念是否由问题自然引出、推理是否连续、例子是否承担解释作用。易变化的事实使用权威来源核对并记录日期；无法验证的内容列为“待核实”，不要补写成事实。
3. **从三个尺度阅读。** 章节尺度检查问题与知识脉络，段落尺度检查因果和过渡，句子尺度检查精确、简洁与术语一致。不能以逐句润色代替结构审查。
4. **检查重复与边界。** 比较章内各节、相邻章节以及正文—卡片—自测。若两处回答同一个问题、提供相同推理且后出现的内容没有增加新条件、新关系或新的应用判断，应合并、缩短为承接句或删除。必要的前情回顾、间隔复习和总结性综合可以保留，但必须服务于新的推理任务，不能把上一章重新讲一遍。
5. **检查学习闭环。** 正文讲解、图示、助记卡、自测题、参考答案必须相互一致；题目只能考正文已经建立的知识，答案不得偷偷引入新前提。卡片可以回忆正文，自测应要求辨析或应用，避免三者仅更换措辞机械复述。
6. **执行机械检查。** 对 Markdown 文件运行 `python scripts/check_markdown.py <文件或目录>`，再人工判断报告；脚本结果是线索，不是最终结论，语义重复仍需人工比较。
7. **按影响处理。** 先修复会造成错误理解或学习断裂的问题，再处理明显阻碍理解的问题和无效重复，最后才处理措辞偏好。不要为了统一格式制造更多分段或模板话术。
8. **复核改动。** 修订后重新通读受影响段落、前后章节和相关题目，运行机械检查与项目已有验证；确认压缩后因果链仍完整，没有改变事实、破坏链接或覆盖用户笔记。

## 反馈格式

审查模式先用两三句话给出总体判断，再列问题。每项应包含：

- **级别：** 严重（可能教错）、重要（明显阻碍理解）、一般（值得改善但不妨碍主线）。
- **位置：** 文件、章节、段落、公式、图或题号，尽量可定位。
- **问题：** 指明实际缺口，不只写“表达不清”。
- **影响：** 说明学习者可能在哪里断掉或形成什么误解。
- **建议：** 给出可执行的修改方向；必要时提供一小段示例，不重写整篇。

将“需要事实核实”和“可由现有内容确定的问题”分开。没有发现的问题不凑数，不把个人文风偏好描述为硬性错误。

修订模式完成后报告：修改范围、最重要的改进、验证结果、仍需用户判断或外部核实的事项。不要在课程正文中留下审查报告或作者提示，除非项目规范要求。

## 边界

- 不编造来源、数据、运行结果、用户作答或掌握状态。
- 不因追求简短删除理解必需的推导步骤，也不因追求完整一次引入多个抽象层次。
- 不机械消灭被动句、长句、术语重复；技术术语保持一致比同义改写更重要。
- 不默认安装工具、运行实验、改变学习路线、提交或推送版本库；只有用户请求或项目工作流明确要求时才做。

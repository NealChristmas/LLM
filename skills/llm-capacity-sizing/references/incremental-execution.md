# 增量执行与证据复用

## 开始先判断变化

| 本轮变化 | 执行动作 |
| --- | --- |
| 仅报告措辞、排版 | 读取已保存结果并重新渲染，不重算、不联网 |
| 并发、长度、时延、增长、备用或已授权预算值 | 复用匹配的模型适配器及固定证据，重算依赖项并执行对应检查 |
| 模型修订、量化实现、框架缓存或部署布局 | 核对受影响部分，必要时重新适配；未受影响证据继续复用 |
| 首次评估或证据缺失 | 先取足以确定算法的官方config、说明、索引和必要实现，再按缺项扩大获取范围 |

复用身份须核对模型提交、config摘要、量化与缓存格式、框架实现、部署布局及卡/Device单位。旧文件存在不等于适用；旧结论不替代本轮计算。固定版本文件有摘要且内容有效时不重新下载；本轮要求最新资料时另行核对版本。

## 控制最重的步骤

- 先检查本地来源清单和已验证脚本。固定证据首次使用或身份变化时校验；本轮重复阶段不反复全量读取。
- 权重估算优先采用足够可靠的官方参数清单、索引或已有张量摘要。只有混合量化、特殊模块等确实影响当前结论且现有资料不足时，才读取权重文件头。不要每轮遍历全部分片。
- 不下载完整权重，不扫描无关仓库，不默认获取全部实现文件。独立且必需的小文件可并行取得，失败只重试缺失项。
- 数值脚本与资料获取分离；预算假设保留在显式输入中。重算不应隐式联网，报告生成不应隐式重算。
- 同一轮结果写成一个结构化文件，报告只读取该结果。记录本轮复用项、新获取项、重算项和实际阶段耗时；未测量前不承诺提速比例。

## 报告修改与验证

仅改第三章时，保持需求、算法、预算取值与卡数不变。核验数值与结果文件一致、较小配置比较、备用未参加工作负载、基线证据等级未升级。计算脚本变化才执行相关数值测试；不因措辞修改重复下载证据或运行全套适配。
